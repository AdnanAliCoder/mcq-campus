# MCQ Campus — Django + Supabase + Render deployment

This repository is prepared as one same-origin application:

- Frontend: existing MCQ Campus HTML/CSS/JS
- Backend: Django JSON API under `/api/`
- Database: PostgreSQL (Supabase)
- Hosting target: Render web service
- Static assets: WhiteNoise

## 1. Create Supabase project

1. Sign in to Supabase and create a new project.
2. Save the database password somewhere private.
3. Open **Connect** in the Supabase project.
4. Copy the **Shared Pooler / Session mode** PostgreSQL connection string (port 5432).
5. Do not paste this connection string into GitHub source files.

Use it later as Render environment variable `DATABASE_URL`.

## 2. Push this folder to GitHub

Create a repository and upload the contents of this ZIP at repository root. `manage.py`, `render.yaml`, `requirements.txt`, `frontend/`, `core/`, and `mcqcampus/` should all be at the top level.

Do not upload a real `.env` file. The included `.gitignore` should keep secrets out of Git.

## 3. Create Render service

The repository includes `render.yaml`. Create a Render Blueprint/Web Service from the GitHub repository.

Required environment variables:

- `DATABASE_URL` = Supabase session pooler connection string
- `SUPERADMIN_EMAIL` = your owner login email
- `SUPERADMIN_PASSWORD` = a strong password (Render secret only)
- `SUPERADMIN_NAME` = display name
- `SECRET_KEY` = generated by Render or another long random secret
- `DEBUG` = `false`

The build runs:

1. Python dependency installation
2. static asset collection
3. Django built-in migrations + initial core table sync
4. bundled category/paper/MCQ seed import
5. Super Admin account creation/update

## 4. First login

Open the deployed site and log in using `SUPERADMIN_EMAIL` and `SUPERADMIN_PASSWORD`.

The Super Admin panel includes:

- Users / Admins
- Roles & permissions
- Admin performance
- Categories / subcategories / child categories
- Papers / jobs / job years
- MCQ add/edit/review/import
- Site content / SEO / settings
- Google Analytics + Google AdSense management
- Custom company advertisements and AdSense slot placements
- Reports, activity logs, backup/export and recovery views

## 5. Analytics and ads

Open **Super Admin → Analytics & ads**.

### Google Analytics
Paste either:

- the complete Google Analytics script, or
- only the `G-XXXXXXXXXX` measurement ID.

The backend extracts the measurement ID and inserts the official Google tag into the page head. Toggle **Enable Google Analytics** to activate/deactivate it.

### Google AdSense
Paste either:

- the complete AdSense script, or
- only the `ca-pub-...` client ID.

Toggle **Enable Google AdSense** to activate/deactivate the global AdSense script.

Use **Ad placements** to create:

- custom company ads (image URL + destination URL), or
- AdSense slots (slot ID).

## 6. Important security rules

- Never commit Supabase database passwords, Django `SECRET_KEY`, or owner passwords.
- Keep the Supabase connection string only in Render environment variables.
- The browser never receives the database password.
- Regular Admin accounts are permission-controlled. Super Admin retains owner-level controls.
- Google Analytics and AdSense configuration is owner-only.

## 7. Local development (optional)

Create a `.env` from `.env.example` and export the values in your shell, then run:

```bash
python -m venv .venv
# activate the environment
pip install -r requirements.txt
python manage.py migrate --run-syncdb
python manage.py import_seed
python manage.py ensure_superadmin
python manage.py runserver
```

For a first local test you can omit `DATABASE_URL`; Django will use SQLite. Production should use Supabase PostgreSQL.
